Автор: студент 1 курса РАНХиГС (ОАФ, Прикладная информатика), команда из одного человека.
Основной ИИ-ассистент: **Claude** (claude.ai, режим агента с инструментами: код, браузер для проверки, публикация артефактов).

## Этапы

### 0. Набросок (другая нейросеть)
Первый вариант кабинета: главная, расписание, успеваемость, МФЦ, секции, волонтёрство, студбилет с QR. Данные только в браузере, без входа, без названия вуза.

### 1. Разбор ТЗ с Claude (18 ноября)
Промпт: «я в хакатоне участвую, мне надо навайбкодить ЛК моего вуза (РАНХиГС), какие инструменты нужны и какие фишки добавить» → затем ТЗ кейса целиком.
Claude сверил набросок с обязательным ядром и нашёл дыры: нет входа и профиля, нет переносов, нет блока сессии, нет ленты деканата, нет пометки «концепт», данные в браузере (не пройдёт критерий «Имплементация»), ссылка claude.ai не открывается из РФ без VPN.
Решение: **сначала весь визуал в артефакте, потом перенос на сервер**.

### 2. Визуальный прототип (18–20 ноября) — ключевые итерации
1. Экран входа + 2 тестовых студента + профиль, переносы в расписании, сессия и зачётка, новости, свой логотип, плашка «концепт».
2. **«Главная перегружена»** → убрали карточку МФЦ, дедлайны свернули до 3, плашку переносов — в одну строку.
3. **Критика пользователя: «плашка со средним баллом будет бесить всех, у кого ниже 4»** → средний балл убран с главной, вместо него карточка «На этой неделе» с действиями («сдай ИДЗ — и будет допуск»), тон поддерживающий; успеваемость разбита на вкладки «Текущий семестр / Сессия / Зачётка».
4. Сравнение с **реальным ЛК РАНХиГС** (скриншоты): непонятные полоски баллов без шкалы, посещаемость таблицей «план/факт», 11 пунктов меню, огромные карточки пар → у нас: баллы из 100 с прогнозом, 6 пунктов меню, компактное расписание.
5. «Вкладка мероприятий на пол-экрана бесит» → мероприятия, секции, волонтёрство объединены в «Студенческую жизнь»; на главной — только то, куда записан.
6. Цвет: тёплые нейтральные вместо холодных серых — «бордо академии, но дороже».
7. **Реальное расписание** первокурсника ПИ со скриншотов: пары по 80 минут, 5 пар, суббота, корпуса и аудитории; **чередование чётных/нечётных недель** до Нового года. Преподаватели — вымышленные (требование ТЗ).
8. Недельная сетка по номерам пар — как в оригинале видно, «к какой паре идти», пустые пары пунктиром.
9. Секции: «Мои секции» + каталог, переключатель «Добавить в моё расписание», проверка пересечений с парами.
10. ИИ-помощник «Спроси деканат», кабинет сотрудника деканата, тёмная тема.
11. Поиск по всему кабинету (Ctrl+K), карточка и расписание преподавателя, состояния загрузки/ошибки/нет сети.

### 3. Ошибки ИИ и как их исправляли (для отчёта — важно)
- **ИИ-помощник отвечал не на тот вопрос**: «на какое мероприятие волонтёрства я могу пойти сейчас» → он увидел слово «сейчас» и рассказал про следующую пару. Причина: тема «пары сейчас» проверялась раньше остальных. Исправление: сначала определяем тему (волонтёрство, дедлайны, переносы), «сейчас» — только уточнение; добавлена тема «волонтёрство».
- **Двойная точка** «Морозова А. В..» в ответе ассистента.
- **Отработки и запись на консультации** — Claude добавил то, чего в РАНХиГС нет. Пользователь поправил → убрано, вместо консультаций — «Расписание преподавателя». Правило записано в CLAUDE.md.
- **Тёмная тема получилась «неоновой»** (яркий красный, свечения, жёлтые заливки) → переделана в спокойную графитовую с тонкими цветными полосками вместо заливок.
- **Технические баги, пойманные автопроверкой Claude на скриншотах:** вкладка «Профиль» оказалась вложена внутрь другого раздела и не открывалась; на телефоне экран входа обрезался; конфликт CSS-классов (`.demo`, `.me`, `.study`) ломал вид карточек; круглый таймер дедлайна в тёмной теме оставался белым; при отправке заявки из ИИ кнопка удалялась раньше, чем на неё ссылался код (ошибка в консоли).
- **Артефакт не открывался у пользователя** (сетевые ограничения claude.ai из РФ) → Claude дополнительно отдавал офлайн-копию файлом.

### 4. Перенос на сайт (20–21 ноября)
- Сервер `server.js` без внешних библиотек: `node:http`, `node:sqlite`, `node:crypto` — чтобы деплой на Amvera не зависел от npm.
- Личные данные студентов вынесены из кода страницы в базу (скрипт выгрузил их из прототипа автоматически).
- Вход: scrypt + соль, токен сессии в HttpOnly-cookie, в базе только хэш токена, блокировка перебора.
- Разделение данных: API не принимает id студента; `/api/staff/*` — только сотрудник (проверено: студент получает 403).
- Заявки и объявления — в базе: сотрудник меняет статус → студент получает уведомление при следующем входе.
- ИИ-помощник: настоящая нейросеть через сервер (YandexGPT или GigaChat), ключ только в переменных окружения; без ключа — правила.
- Автотест в браузере: вход двумя студентами и сотрудником, заявка через ИИ → «в работе» → «готово» → уведомление у студента, объявление для группы ПИ-26-1 видно только этой группе, состояние (записи в секции) сохраняется после перезагрузки.
