# Цифровой деканат — концепт личного кабинета студента РАНХиГС

> **Концепт для конкурса «Цифровой деканат будущего».** Не является официальным сервисом РАНХиГС.
> Все имена, оценки, номера зачёток и прочие данные вымышлены. Логотип собственный.

Личный кабинет, где всё учебное собрано в одном месте: расписание с переносами, дедлайны, баллы и сессия, справки онлайн со статусами, объявления деканата, секции и мероприятия, ИИ-помощник. Работает с телефона (от 360 px) и с компьютера.

## Тестовые аккаунты

| Роль | Логин | Пароль | Что показать |
|---|---|---|---|
| Студентка, 3 курс ГМУ | `student1` | `demo2026` | всё в порядке, допуск ко всем экзаменам |
| Студент, 1 курс, Прикладная информатика | `student2` | `demo2026` | реальное расписание РАНХиГС (чётные/нечётные недели), нет допуска по линейной алгебре |
| Сотрудник деканата | `dekanat` | `demo2026` | очередь заявок всех студентов, смена статусов, объявления |

**Сценарий проверки:** войти как `student2` → в ИИ-помощнике написать «закажи справку в военкомат» → «Подать заявку» → выйти → войти как `dekanat` → «Принять в работу» → «Готово» → снова войти как `student2` — придёт уведомление «Заявка готова».

## Как устроено

```
браузер (public/index.html)  ──HTTPS──▶  server.js (Node.js, без зависимостей)  ──▶  SQLite (/data/dekanat.db)
                                               └──▶ YandexGPT / GigaChat (необязательно, ключ только на сервере)
```

- **Сервер** — `server.js`, только встроенные модули Node.js ≥ 22.13: `node:http`, `node:sqlite`, `node:crypto`. Нечему ломаться при установке, нет уязвимых зависимостей.
- **База** — SQLite-файл в постоянном хранилище (`DATA_DIR`, на хостинге `/data`). При первом запуске заполняется вымышленными данными из `seed/`. Для роста числа пользователей схема переносится на PostgreSQL без изменения API.
- **Фронтенд** — одна страница `public/index.html` (HTML + CSS + JS без фреймворков). Личных данных в ней нет: всё приходит с сервера после входа.

## Безопасность

- **Пароли** хранятся только как хэш **scrypt** с уникальной солью (`seed/accounts.json` содержит хэши, не пароли). Проверка — с защитой от атаки по времени (`timingSafeEqual`, фиктивный хэш для несуществующих логинов).
- **Сессии** — случайный 256-битный токен в cookie `HttpOnly; SameSite=Lax; Secure`. В базе хранится только SHA-256 от токена. Выход удаляет сессию на сервере.
- **Каждый видит только своё.** Ни один адрес API не принимает id студента: сервер берёт пользователя из сессии (`/api/me`, `/api/requests`, `/api/state`). Подставить чужой id некуда. Разделы `/api/staff/*` доступны только роли «сотрудник» (иначе 403).
- **Перебор паролей**: после 5 ошибок вход блокируется на 30 секунд.
- **CSRF**: изменяющие запросы принимаются только со своего сайта и только с заголовком `X-Requested-With`.
- **Заголовки**: Content-Security-Policy, `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`.
- **Ограничения**: размер запросов, частота заявок и вопросов к ИИ, белый список типов заявок и смен статусов.
- **Ключи ИИ** — только в переменных окружения сервера, в коде и в браузере их нет.

## Запуск локально

```bash
node server.js          # http://localhost:3000
```

## Деплой (Amvera)

Проект содержит `Dockerfile` и `amvera.yml` (порт 3000, постоянное хранилище `/data`). Загрузить файлы через интерфейс Amvera или `git push`.

Необязательные переменные окружения для настоящей нейросети в ИИ-помощнике:
- YandexGPT: `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`
- или GigaChat: `GIGACHAT_AUTH_KEY` (+ при необходимости `NODE_EXTRA_CA_CERTS` с сертификатом Минцифры)

Без ключей помощник отвечает по встроенным правилам на основе данных студента.

## Структура

```

tools/build_site.py    сборка фронтенда сайта из прототипа
tools/site_client.js   клиентская часть: вход, данные, заявки через API
docs/                  описание процесса работы с ИИ
CLAUDE.md              правила проекта для ИИ-агента
```
