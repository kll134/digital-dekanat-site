# Цифровой деканат — концепт личного кабинета студента РАНХиГС

> **Концепт для конкурса «Цифровой деканат будущего».** Не является официальным сервисом РАНХиГС.
> Все имена, оценки, номера зачёток и прочие данные вымышлены. Логотип собственный.

Личный кабинет, где всё учебное собрано в одном месте: расписание с переносами, дедлайны, баллы и сессия, справки онлайн со статусами, объявления деканата, секции и мероприятия. Работает с телефона (от 360 px) и с компьютера.

## Тестовые аккаунты

| Роль | Логин | Пароль | Что показать |
|---|---|---|---|
| Студентка, 2 курс ГМУ | `student1` | `demo2026` | всё в порядке, допуск ко всем экзаменам |
| Студент, 1 курс, Прикладная информатика | `student2` | `demo2026` | демо-расписание первого курса прикладной информатики, нет допуска по линейной алгебре |
| Сотрудник деканата | `dekanat` | `demo2026` | очередь заявок всех студентов, смена статусов, объявления |

**Сценарий проверки:** войти как `student2` → в разделе «Справки и заявления» подать тестовую заявку → выйти → войти как `dekanat` → «Принять в работу» → «Готово» → снова войти как `student2` — придёт уведомление «Заявка готова».

## Как устроено

```
браузер (public/index.html)  ──HTTPS──▶  server.js (Node.js)  ──▶  SQLite (/data/dekanat.db)
```

- **Сервер** — `server.js`, только встроенные модули Node.js ≥ 22.13: `node:http`, `node:sqlite`, `node:crypto`. Нечему ломаться при установке, нет уязвимых зависимостей.
- **База** — SQLite-файл в постоянном хранилище (`DATA_DIR`, на хостинге `/data`). При первом запуске заполняется вымышленными данными из `seed/`. Для роста числа пользователей схема переносится на PostgreSQL без изменения API.
- **Фронтенд** — одна страница `public/index.html` (HTML + CSS + JS без фреймворков). Личных данных в ней нет: всё приходит с сервера после входа.

## Безопасность

- **Пароли** хранятся только как хэш **scrypt** с уникальной солью (`seed/accounts.json` содержит хэши, не пароли). Проверка — с защитой от атаки по времени (`timingSafeEqual`, фиктивный хэш для несуществующих логинов).
- **Сессии** — случайный 256-битный токен в cookie `HttpOnly; SameSite=Lax; Secure`. В базе хранится только SHA-256 от токена. Выход удаляет сессию на сервере.
- **Каждый видит только своё.** Ни один адрес API не принимает id студента: сервер берёт пользователя из сессии (`/api/me`, `/api/requests`, `/api/state`). Подставить чужой id некуда. Разделы `/api/staff/*` доступны только роли «сотрудник» (иначе 403).
- **Перебор паролей**: после 5 ошибок вход блокируется на 30 секунд.
- **CSRF**: изменяющие запросы принимаются только со своего сайта и только с заголовком `X-Requested-With`.
- **Заголовки**: Content-Security-Policy, `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`.
- **Ограничения**: размер запросов, частота заявок, белый список типов заявок и смен статусов.

## Реальное расписание и кабинет сотрудника (22.11.2026)
- Часы и дата синхронизируются с сервером через публичный `/api/clock`; весь интерфейс форматирует время в `Europe/Moscow`, независимо от часового пояса устройства.
- Главная выбирает день недели и учебную неделю автоматически. Карточка «Сегодня» показывает пары текущего дня; во время пары отображается «Идёт сейчас» и обратный отсчёт до её окончания, следующая пара отмечается отдельно. По воскресеньям выводится корректное пустое состояние.
- Если сотрудник или студент открыл сайт из другого часового пояса, календарь всё равно ориентируется на московское время кампуса.
- Кабинет методиста включает обзор очереди обращений, фильтры и поиск по студентам/типам заявлений, переходы по статусам «Новая → В работе → Готово/Отклонено», каталог 18 демонстрационных учебных профилей (2 основных аккаунта для входа и 16 дополнительных карточек каталога), карточку студента с успеваемостью/расписанием/обращениями/сданными работами, а также публикацию и снятие объявлений для всех студентов или выбранной группы.
- Все операции сотрудника выполняются через защищённые `/api/staff/*` маршруты и записываются в SQLite; роль студента получает 403 на эти маршруты.
- Для расписания используется календарная неделя с понедельника, начиная с 9 ноября 2026 года; шаблоны чётной и нечётной недели применяются автоматически. Время начала и окончания пары сравнивается с серверным временем, а не с фиксированной демонстрационной датой.


## Актуальное состояние: живое расписание и кабинет сотрудника (22.11.2026)

- Расписание на главной привязано к часовому поясу `Europe/Moscow`: клиент синхронизирует часы с `/api/clock`, самостоятельно выбирает календарный день и учебную неделю. При смене дня/недели блок главной и расписание обновляются автоматически.
- Во время пары карточка показывает «Идёт сейчас», аудиторию/формат, индикатор хода занятия и оставшееся время. Следующая пара и завершённые занятия различаются; в воскресенье показывается пустое состояние без вымышленных пар.
- Кабинет сотрудника содержит обзор очереди обращений, поиск и фильтры заявок, перевод обращения из «Новая» в «В работе», далее в «Готово» или «Отклонено» с причиной, которую видит студент.
- В каталоге сотрудник находит 18 демонстрационных учебных профилей и открывает карточку: факультет, направление, курс, группа, успеваемость, посещаемость, расписание на текущий день, последние обращения и отправленные работы.
- Прикреплённые студентами файлы доступны сотруднику для скачивания из карточки. Сервер проверяет роль сотрудника и безопасное имя внутреннего файла; студент не может обращаться к `/api/staff/*`.
- Сотрудник может опубликовать объявление с категорией для всех студентов или конкретной учебной группы, а также снять объявление с публикации. Содержание хранится в SQLite и показывается нужным студентам.
- Для проверки использовалась отдельная временная база, не `/data` Amvera.


## Обновление: расшифровка БРС и расширенный каталог методиста (22.11.2026)
- В расписании на главной, в подробном расписании дня и в недельной сетке показывается основание начисления БРС: устный ответ, посещение, работа у доски, практическая задача, участие в обсуждении и т. п. У нулевого начисления выводится пояснение, что занятие прошло без оценивания.
- Указанные начисления и основания — вымышленные демонстрационные данные конкретных занятий. Они не заявляются как официальный регламент балльно-рейтинговой системы РАНХиГС.
- Каталог методиста расширен до 18 учебных профилей: два основных демонстрационных аккаунта и 16 дополнительных карточек без возможности входа. Дополнительные ФИО, группы, оценки и посещаемость вымышлены. Названия образовательных направлений сверены с опубликованным перечнем программ РАНХиГС: https://www.ranepa.ru/bakalavriat/
- Для дополнительных карточек используются направления, представленные в официальном перечне программ бакалавриата РАНХиГС: прикладная математика и информатика, прикладная информатика, экономика, менеджмент, ГМУ, бизнес-информатика, социология, юриспруденция, регионоведение России, политология, международные отношения, публичная политика и социальные науки, реклама и связи с общественностью, медиакоммуникации, гостиничное дело и история.
- В личные кабинеты двух основных студентов добавлены демонстрационные обращения: Анастасии — справка для военкомата (в работе), Максиму — замена студенческого билета (ожидает обработки). Они также отображаются в очереди сотрудника.
- При старте сервера выполняется идемпотентная добавочная синхронизация: новые записи добавляются один раз, уже существующие профили дополняются только пустыми полями, заявки и данные из `/data` не очищаются и не пересоздаются.

## Обновление: реалистичные демонстрационные начисления БРС (22.11.2026)
- Для посещения занятия без дополнительной активности используются небольшие демонстрационные начисления: 0,5 БРС за лекцию, 0,75 за семинар/практику и 1 БРС за занятие по физической культуре.
- За устные ответы, участие в обсуждении, решение задач и выполненные практические задания начисляются отдельные более высокие демонстрационные значения.
- Дробные значения показываются с десятичной запятой. Пояснения видны на главной, в дневном расписании и в недельной сетке.
- Причины начислений являются вымышленными примерами для прототипа, не официальным регламентом РАНХиГС.
- Для текущей и уже прошедших учебных недель отметки БРС сохраняются; в расписании будущих недель они не показываются заранее.
